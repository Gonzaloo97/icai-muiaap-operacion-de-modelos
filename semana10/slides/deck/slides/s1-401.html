HTTP/1.1 401 Unauthorized

{

    "code": "unauthorized",
    "message": "Missing or invalid API key"
  },
  "request_id": "req_3f9a1c2b7d4e"
}

El 401 dice «no sé quién eres».

WWW-Authenticate indica cómo identificarse.

El cliente programa contra code, como en S9.

El mensaje no revela si la clave existía.

11

Cierre del bloque 1 (4 min). El error de autenticación no es especial: usa el mismo sobre de S9 (error.code, error.message y request_id, igual a la cabecera X-Request-Id). En la práctica (S10.2) se añade ErrorCode.UNAUTHORIZED y la clase AuthenticationError, y WineApiError pasa a admitir cabeceras por instancia para enviar WWW-Authenticate sin perder X-Request-Id. Mismo mensaje para clave ausente y clave incorrecta: si distinguiera «esa clave no existe» de «esa clave existe pero está caducada», daría pistas a quien prueba claves. Comprobación que el alumnado puede hacer: curl -i http://127.0.0.1:8000/v1/scores sin cabecera debe mostrar el 401 con WWW-Authenticate; con -H "X-API-Key: TU_API_KEY" debe dar 200. El texto exacto del message lo fija el código del módulo; lo que se prueba es el code y el status.
