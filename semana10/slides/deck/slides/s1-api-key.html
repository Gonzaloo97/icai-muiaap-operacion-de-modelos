def get_client(api_key: Annotated[str | None, Security(api_key_header)]) -> Client:
    for client in CLIENTS:
        if api_key and secrets.compare_digest(api_key, client.key):
            return client
    raise HTTPException(
        status_code=401, detail="Invalid API key", headers={"WWW-Authenticate": "ApiKey"}
    )

Lectura línea a línea: APIKeyHeader declara que la credencial viaja en la cabecera X-API-Key; además de leerla, la registra como securityScheme en OpenAPI, así que /docs muestra el botón Authorize. auto_error=False hace que FastAPI no responda por su cuenta si falta la cabecera: así controlo yo el status (401) y la cabecera WWW-Authenticate; con auto_error=True devolvería su propio error, sin nuestro sobre. Security(...) es como Depends pero añade la información de seguridad al esquema. get_client devuelve el cliente identificado, no un booleano: las rutas reciben quién llama. ClientDep es el alias Annotated que ya usamos en S8 y S9 con PredictorDep. En la práctica, este HTTPException se sustituye por AuthenticationError, del sobre de error de S9. Pregunta: ¿por qué recorro todos los clientes en vez de usar un dict con la clave como índice? Porque la búsqueda en dict no es de tiempo constante; compare_digest sí.
