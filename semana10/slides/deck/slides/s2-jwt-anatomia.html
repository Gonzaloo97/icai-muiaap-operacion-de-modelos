Anatomía de un JWT (JSON Web Token, RFC 7519), 5 min. Son tres trozos en Base64URL separados por puntos. Header: el algoritmo de firma. Payload: los claims. sub (subject): quién es. scope: qué puede hacer, separado por espacios si hay varios. iss (issuer): quién emitió el token. aud (audience): para qué API es. exp (expiration): instante de caducidad en segundos Unix. Signature: firma del header y el payload; con HS256 es un HMAC con una clave compartida; con RS256 o ES256 el IdP firma con su clave privada y la API valida con la pública. Analogía: es una pulsera de festival con fecha y zonas impresas y un holograma: cualquiera puede leer las zonas, pero nadie puede falsificar el holograma. Diferencia con la API key: la API consulta su lista de claves; con un JWT no consulta a nadie, le basta la firma, por eso escala bien, pero revocar antes de exp es difícil y se usan caducidades cortas (15 min en la demo). Abre jwt.io con un token de la demo para mostrar que el payload se lee sin la clave.
