bearer = HTTPBearer(auto_error=False)

def get_claims(
    credentials: Annotated[HTTPAuthorizationCredentials | None, Security(bearer)],
) -> dict:
    if credentials is None:
        raise HTTPException(401, "Missing token", headers={"WWW-Authenticate": "Bearer"})
    try:
        return jwt.decode(credentials.credentials, SECRET_KEY, algorithms=["HS256"],
                          audience="wine-api", issuer="muiaap-demo-idp")
    except jwt.InvalidTokenError:
        raise HTTPException(401, "Invalid token", headers={"WWW-Authenticate": "Bearer"})

Fragmento literal de examples/jwt_demo.py (5 min), con PyJWT. HTTPBearer lee la cabecera Authorization: Bearer <token> y la registra en OpenAPI. Igual que con la API key, auto_error=False para controlar el 401 y su cabecera WWW-Authenticate: Bearer. jwt.decode hace tres cosas a la vez: verifica la firma con SECRET_KEY, comprueba exp (caducidad) y compara aud e iss con lo que espero. Cualquier fallo lanza una subclase de InvalidTokenError (ExpiredSignatureError, InvalidAudienceError, InvalidIssuerError...), y todas acaban en 401. La demo tiene un POST /token que emite tokens firmados (sub, scope, iss, aud y exp a 15 minutos) solo para poder probar, y un GET /v1/me protegido que devuelve los claims. SECRET_KEY se lee del entorno; el valor por defecto está marcado como «solo demo». En la demo en vivo (paso 3) emitimos un token, lo validamos y probamos uno caducado y otro con otra audiencia. Los scopes del token se comprueban igual que en require_scope, leyendo el claim scope.
