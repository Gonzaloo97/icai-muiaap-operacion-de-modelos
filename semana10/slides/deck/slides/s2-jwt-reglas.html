Cuatro reglas para JWT

Fijo algorithms al decodificar y nunca acepto el algoritmo "none".

Valido exp, iss y aud: una firma correcta no basta.

El payload es Base64 legible: nunca guardo secretos dentro.

En empresa valido tokens de un IdP; no construyo mi propia identidad.

17

Cierre del bloque 2 (3 min). 1) Algoritmo fijo: si dejo que el header del token elija el algoritmo, un atacante puede mandar alg "none" (sin firma) o confundir una clave pública con una clave HMAC. PyJWT exige el parámetro algorithms precisamente por esto. 2) exp, iss y aud: un token bien firmado para otra API (otra audiencia) o ya caducado no debe valer aquí. 3) Base64 no es cifrado: cualquiera puede leer el payload en jwt.io; no meto contraseñas, datos personales innecesarios ni la API key. 4) En empresa la identidad la gestiona un IdP (Entra ID, Okta, Keycloak, Auth0) mediante OIDC; mi API solo valida los tokens que emite, con las claves públicas publicadas en su endpoint JWKS. El POST /token de la demo existe solo para aprender: no es un patrón para producción. Pregunta de cierre: ¿por qué un exp de 15 minutos y no de un mes? Porque un JWT no se puede revocar fácilmente; una caducidad corta limita el daño si se filtra.
