Configuro CORS de forma explícita

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:8501"],
    allow_methods=["GET", "POST"],
    allow_headers=["Content-Type", "X-API-Key"],
    expose_headers=["X-Request-Id"],
)

Enumero los orígenes y nunca uso "*" con credenciales.

Con expose_headers el front lee X-Request-Id.

Los orígenes salen de la configuración.

CORS no sustituye a la API key.

Fragmento literal de examples/cors_demo.py (4 min). allow_origins: lista cerrada de orígenes exactos, con esquema y puerto. El comodín "*" está prohibido junto a credenciales (cookies o cabecera Authorization) por la propia especificación, y aun sin credenciales abre la API a cualquier web; en la práctica no se usa nunca. allow_methods y allow_headers: solo lo que el front necesita. expose_headers: por defecto el JavaScript solo puede leer unas pocas cabeceras de respuesta; si quiero que el front muestre el X-Request-Id en un mensaje de error (S6), tengo que exponerlo. En la práctica (S10.5) se exponen también Retry-After y X-RateLimit-Remaining, y allow_origins viene de settings.cors_origins, es decir, de la variable WINE_API_CORS_ORIGINS. Error típico: poner el origen con barra final (http://localhost:8501/), que no coincide con la cabecera Origin. Cierre del bloque: CORS es una política del navegador; la seguridad de la API sigue en la API key y los scopes.
