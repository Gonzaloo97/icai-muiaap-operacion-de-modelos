Cierre de la teoría (2 min). OWASP API Security Top 10, edición 2023, es la lista de referencia de riesgos en APIs. Mapeo lo de hoy a cuatro categorías: API2 Broken Authentication (autenticación débil o mal implementada), API5 Broken Function Level Authorization (un cliente normal llega a funciones de administración), API4 Unrestricted Resource Consumption (sin límites de consumo) y API8 Security Misconfiguration (CORS abierto, documentación expuesta, secretos en el código). docs_enabled=False permite apagar /docs, /redoc y /openapi.json en un despliegue público si así se decide. Lo que no cubrimos y conviene nombrar: API1 Broken Object Level Authorization (un cliente accede a objetos de otro; aquí no hay objetos por usuario) y API9 Improper Inventory Management (versiones antiguas olvidadas expuestas). Pregunta: ¿qué categoría tocaría si /v1/admin/usage devolviera las claves? API3 Broken Object Property Level Authorization, exposición de propiedades sensibles; por eso el endpoint nunca las incluye.
