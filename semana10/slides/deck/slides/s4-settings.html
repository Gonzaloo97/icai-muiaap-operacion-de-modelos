Fragmento literal de examples/limits_demo.py (4 min). pydantic-settings lee variables de entorno (y opcionalmente un fichero .env) y las valida con Pydantic: DEMO_API_KEY rellena api_key, DEMO_RATE_LIMIT_PER_MINUTE rellena el límite y DEMO_CORS_ORIGINS se escribe en JSON, por ejemplo ["http://localhost:8501"]. Si falta api_key, la app no arranca: prefiero un error al arrancar que una API abierta. Field(gt=0) impide un límite de 0 o negativo por error de configuración. SecretStr: print(settings) muestra api_key='**********'; para comparar hay que llamar explícitamente a get_secret_value(). Reglas de repositorio: .env.example documenta qué variables existen con marcadores (cambia-esta-clave), .env tiene los valores reales y está en .gitignore. Fail closed: en la práctica, si WINE_API_CLIENTS está vacío, todo endpoint protegido responde 401 en vez de quedar abierto. En producción los valores vienen de un gestor de secretos (Vault, AWS Secrets Manager, Azure Key Vault) o de las variables del contenedor (S11-S12).
