Un único sobre para todos los errores

{
  "error": {
    "code": "validation_error",
    "message": "JSON is valid but ...",
    "fields": [
      {"field": "features.alcohol",
       "message": "Input should be ..."}
    ]
  },
  "request_id": "req_3f9a1c2b7d4e"
}

El cliente programa contra code, nunca contra message.

fields solo aparece en errores de validación.

request_id coincide con la cabecera X-Request-Id.

Alternativa estándar: RFC 9457, problem+json.

Sin trabajo extra, FastAPI devuelve tres formas distintas: {"detail": [...]} en un 422, {"detail": "Not Found"} en un 404 y texto plano «Internal Server Error» en un 500. El gateway de S7 tendría que conocer las tres. Con un sobre único, el cliente escribe un único parser. RFC 9457 (Problem Details) es el estándar IETF para lo mismo: type, title, status, detail e instance. Lo mencionamos; mantenemos el sobre de S7 porque el cliente ya existe.
